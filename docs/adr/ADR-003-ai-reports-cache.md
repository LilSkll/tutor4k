# ADR-003: Почему AI Reports кэшируются

- **Status:** Accepted
- **Date:** 2026-08-01
- **Module:** Teacher Dashboard / AI

## Context

Карточка ученика должна открываться быстро. Полный AI-анализ (ошибки, прогресс, рекомендации) дорог по токенам и латентности. Пересчёт на каждый pageview недопустим.

## Decision

Вводим **`teacher_ai_reports`** как кэш результата анализа (без `teacher_id`, см. ADR-002).

Генерация через `TeacherAiService` (поверх `ProgressService` / `MistakesService` + существующий AI orchestrator), **не** из Teacher UI напрямую.

### `source_fingerprint`

- Тип: **`varchar(64)`** — hex SHA-256 отчёта о входных данных (агрегаты прогресса, счётчики ошибок, версии ключевых глав и т.п.).
- Перед вызовом AI: посчитать новый fingerprint → сравнить с сохранённым.
  - Равны → **не** вызывать модель, отдать кэш.
  - Различаются или отчёта нет → сгенерировать, записать, обновить fingerprint.

### Когда перегенерировать

1. Нет актуального отчёта (`deleted_at IS NULL`).
2. Fingerprint изменился (прогресс/ошибки сдвинулись).
3. По расписанию (например раз в сутки) — опциональный stale-refresh.
4. После завершения главы учеником — фоновая инвалидация/refresh при наличии active `teacher_students`.
5. Ручная кнопка «Обновить анализ» у преподавателя.

Домашние задания от AI (`assignments.source = ai`) — **только после подтверждения** преподавателем; кэш отчёта ≠ авто-assign.

## Consequences

**Плюсы**

- Карточка ученика открывается из БД за миллисекунды.
- Экономия токенов за счёт fingerprint short-circuit.
- Один канонический отчёт на `(student_id, course_id)`.

**Минусы**

- Нужна дисциплина: все значимые изменения прогресса должны попадать в fingerprint (иначе устаревший вердикт).
- Хранение текста summary/recommendations растёт с числом учеников (на порядки меньше, чем сырые question/answer на каждую ошибку).

## Rejected alternatives

- **Анализ на каждый GET карточки:** дорого и медленно.
- **Только client-side вызов tutor chat:** нет контракта, нет кэша, Teacher UI знает слишком много о AI-пайплайне ученика.
